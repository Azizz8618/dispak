# arfalib — библиотека управления зашифрованными областями АРФА

Объектный модуль **ARFALIB** (том 2348, зона 02570 — сразу за районом
библиотеки ГОСТ 02560) с внешними процедурами для работы с архивными
областями АРФА из любых Паскаль-программ (паттерн — `pasred` в
pascal-re: библиотечный модуль с экспортируемыми точками входа
`(*=e+*)`, `program noprogram`, запись `*to perso`):

* `ARFACRE(nl, nr, n3, sc, ln, ok)` — создать область (Э63 01);
* `ARFADEL(nl, nr, n3, sc, ok)` — уничтожить область (Э63 02);
* `ARFAWRE(nl, nr, n3, sc, nw, zn, iv, ctx, src, ok)` — зашифровать
  ГОСТ 28147-89 (режим CTR, начало гаммы `iv`) и записать `nw`
  alfa-слов в зону `zn` (Э63 12 + Э70);
* `ARFARDD(nl, nr, n3, sc, nw, zn, ctx, dst, ok)` — считать зону,
  расшифровать и выдать `nw` alfa-слов (Э70 + Э63 12).

Имя области — «по-старому»: `nl`, `nr` — слово из 6 букв, `n3` — слово
ещё из 3 букв (код УПП/ГОСТ-10859), `sc` — шифр хозяина. Код ответа
Э63 возвращается через параметр `ok` (0 — выполнено). Контекст ГОСТ
передаётся по ссылке (`var ctx: CtxT`), ключ и s-боксы готовит
вызывающая программа через `GOSTINIT` библиотеки GOSTLIB.

Тест `testarfa.b6`: два зашифрованных отрывка текста (8 и 6 слов)
записываются в зоны 0 и 1 области ТЕКСТ, затем считываются,
расшифровываются и сверяются с эталоном; в конце область уничтожается.
Дека сама чистит остаток прежнего прогона, вывод повторяем.

## Том 2348 после чистки 01.11.26

Компилятор Pascal 15.1 (28.10.26) остался в **единственном**
экземпляре — в самодостаточной библиотеке 02570 (128 модулей:
PASCOMPL + обвязка + GOSTLIB + ARFALIB + runtime, `*perso:402570` —
одна строка загрузки в деках). Удалены экземпляры компилятора в
зонах 02030-02057 (Паскаль-система), 02100-02144 (golden-копия),
02540-02557 (черновая объединённая библиотека) и случайные копии
хвоста Паскаль-системы в 02563-02567. Оставлены: runtime 02000
(запасной, деками не используется), оверлей Паскаля 15.0 в
02060-02062, старая копия GOSTLIB 02500-02506 и действующая
GOSTLIB 02560-02562.

Эталон тома — проект besm-crypto, файл `disk2348`. Перед прогоном
положите его в путь поиска образов:

```sh
cp /путь/к/besm-crypto/disk2348 ../../build/dispak/2348
python3 ../run-test.py
```

(или в сам каталог теста — `--path=.:../../build/dispak` находит оба места).

## Технические заметки

* **Модуль без состояния.** Глобальные переменные объектного модуля
  библиотеки компоновщик размещает поверх данных вызывающей программы
  (isw модуля ложится на смещение 42 кадра задачи — установлено
  тестами). Поэтому всё рабочее состояние (isw, коды ответа,
  лог.номер) — локальные переменные процедур. Контекст ГОСТ —
  только `var`.
* Строки деки — не длиннее 72 символов: карты ввода обрезаются, у
  `external`-объявлений отваливается хвост и компилятор сыплет
  ложные ошибки 84/12/52 в случайных местах.
* Ответы Э63 снимаются с СМ (дозаказ — лог.номер) и М16 (код
  ответа), для канонической целой формы — через поля упакованных
  записей. АИСП — через М6 (`ati 6`, `Э63 (6)`), РМР — `aex (5)`.
* Буферные листы Э70 — страницы 010-013 (020000-027777); слова
  текста передаются половинками по 24 разряда.
* Известная открытая проблема: интерактивная golden-дека
  (besm-crypto, pty-раннер) собирается с 02570 идентично (3529
  строк), но диалог падает на разборе ввода — не компонуется
  модуль P/LV штатного runtime; эталон диалога — `golden_pty.log`
  от 31.10.26 (библиотеки 02030+02000).
